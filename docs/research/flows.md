# Flows

## Method
Repo is empty; this is desk research from the open web (search + fetch), reasoned against established DCC/game-art practice and current (2026) agentic-AI literature. No product decisions were made — see Decisions for every fork left open. Every claim is tagged **observed** (URL, date checked 2026-08-05) or **inferred** (reasoned, not sourced to one claim).

## Operator journeys
Two personas throughout: **(a) prompt-and-watch** — non-artist, judges by "does it look right"; **(b) supervising artist** — judges by topology/scale/production-readiness and corrects directly.

**1. Describe a thing, get a first model.** Entry: empty scene + prompt box (a) or + reference image upload (b), common across Meshy/Tripo3D flows (**observed**, see3d.art / tasarim.ai comparisons, 2026-08-05). Screens: brief -> generation-in-progress -> result, usually multiple candidates — Spline AI returns 4 image previews before committing to 3D (**observed**, docs.spline.design, 2026-08-05). Decision: pick / regenerate / refine in place. Where it breaks: organic/character prompts return "featureless blobs" or anatomically broken meshes, so the "first model" moment fails for exactly the content non-artists ask for most (**observed**, gamedeveloper.com "How devs can spot AI-generated 3D models", 2026-08-05).

**2. Watch a build happen live.** Entry: same session, generation runs as a visible sequence rather than one shot — the "live" differentiator vs. single-shot generate-and-wait tools. Screens: live viewport + running action log (see Decision on what the operator sees). Decision: keep going / pause. Where it breaks: long-running agents with no progress indicator leave users unable to tell "still working" from "stalled" (**observed**, GitLab issue #1351 technical-writing team-tasks; uxtigers.com "Slow AI: Designing User Control for Long Tasks", 2026-08-05).

**3. Stop / steer an agent mid-build.** Entry: a pause/stop/redirect control during journey 2. Screens: paused state showing exactly where the agent stopped, a queue of in-flight vs. committed changes. Decision: resume / roll back N steps / redirect. Where it breaks: the current reference implementation has no built-in checkpoint — its README tells users to "ALWAYS save your work before using" the code-exec tool, i.e. undo is the operator's job (**observed**, github.com/ahujasid/blender-mcp, 2026-08-05).

**4. Point at what's wrong, have it fixed.** Entry: result/in-progress screen, operator selects a region/object. Screens: selection -> agent's diagnosis -> proposed fix -> before/after compare. Decision: accept / reject / re-describe. Personas diverge hardest here: (a) wants "the railing looks off," (b) wants to click the offending edge loop. Where it breaks: AI models are typically single-piece meshes not divided into meaningful parts, so "point at the railing" often has no clean target to hand the agent (**observed**, gamedeveloper.com, 2026-08-05).

**5. Export a finished asset.** Entry: result screen, export button. Screens: format/target picker -> validity check -> download/hand-off. Decision: export as-is / fix flagged issues first. Where it breaks: defects invisible in the viewer (non-manifold geometry, missing PBR maps, UV stretching) surface only once dropped into a downstream tool, making export the moment of maximum disappointment (**observed**, tripo3d.ai "Why AI 3D Models Fail and How to Fix Them", 2026-08-05).

## The agent loop (perceive / plan / act / verify) — the core section
The agent has no eyes and no persistent spatial memory between calls; every stage here has to be engineered, not assumed.

**Perceive.** Four channels, not mutually exclusive:
- *Structured scene-graph text* (objects, transforms, bounding boxes, hierarchy, material refs). Cheap, exact, diffable — GraLa3D and I-Design both reduce the scene to a flat text scene-graph with bounding boxes before reasoning (**observed**, arxiv.org/html/2412.20473; arxiv.org/pdf/2404.02838, 2026-08-05). Blind to anything not encoded — surface quality, silhouette, whether "non-overlapping" boxes read as one coherent shape.
- *Rendered images from N viewpoints.* The only channel that catches what a human eye catches. Costs real tokens — roughly (width×height)/750 for Anthropic models, so a 1024x1024 multi-view set runs several thousand tokens per check (**observed**, roboflow.com "What does it cost to process an image with a vision model?", 2026-08-05) — and current research is explicit that 2D-backbone VLMs still tend to catalogue objects rather than truly understand the 3D scene (**observed**, arxiv.org/html/2605.20448, 2026-08-05). Newer 3D-native VLMs (Qwen-3D, N3D-VLM, GR3D) inject explicit 3D coordinates rather than relying on flat images, which is where the research is heading (**observed**, arxiv.org/html/2608.02980; arxiv.org/pdf/2512.16561, 2026-08-05).
- *Measurements / bounding-box and overlap checks.* Deterministic and cheap; directly catches "railing clips through the floor" via bounding-volume intersection (AABB trees), a standard collision-detection technique reusable as an agent-callable tool rather than a rendering judgment call (**observed**, meshlib.io collision-detection docs, 2026-08-05).
- *Diff since last action.* Feed the agent only what changed, not the whole graph every turn — the same economy argument behind screenshot-diff tools for coding agents (**observed**, github.com/chickencoder/agent-image-diff, 2026-08-05).

Recommended combination (**inferred**): scene-graph diff every call (cheap, always-on) + deterministic geometry/overlap checks as a hard gate + multi-view render only at phase boundaries or on request, since that is where the token cost is worth paying.

**Plan.** Decompose the request into typed operations from a skill library, not free-form code — mirrors "solver-grounded" CAD agents that select from a stratified library of typed geometric operations rather than writing geometry from scratch (**observed**, arxiv.org/abs/2606.31252 "Embodied CAD", 2026-08-05).

**Act.** Execute one typed operation and get structured feedback back (success/failure, resulting bounding box, topology summary) rather than assuming success — exactly what Embodied CAD's solver returns after each action (**observed**, same source).

**Verify.** No human in the loop by default, so verification must be mechanical first, rendered judgment second:
- Deterministic mesh checks: manifoldness, self-intersection (AABB-tree triangle tests), watertightness (**observed**, meshlib.io; dl.acm.org/doi/10.1016/j.gmod.2014.09.002, 2026-08-05).
- Render-and-compare: render the new state, diff against the prior render or a target, reject degenerate changes — demonstrated for 2D vector-graphics agents as "Render-and-Verify" and a direct analog for a 3D viewport diff (**observed**, arxiv.org/pdf/2604.20730, 2026-08-05).
- Multi-view reconstruction consistency: compare renders from several cameras against what the geometry should produce, per Carve3D's reward signal for multi-view diffusion (**observed**, search summary citing Carve3D, 2026-08-05) — inferred to generalize as a self-consistency check.
- Symbolic/constraint verification: for CAD-adjacent structure (stairs, railings, joints), a constraint solver rejecting invalid geometry is a stronger guarantee than any visual check (**observed**, Embodied CAD, 2026-08-05).

**Recover.** No evidence any current live-3D-agent tool has a real answer yet — BlenderMCP has none (**observed**, above). Adjacent practice to borrow: coding-agent checkpoint/rollback (save state per significant action, cheap branch-and-discard via git-worktree-style isolation) (**observed**, digitalapplied.com "Agent Rollback and Checkpoint Patterns"; freestyle.sh "Version Control for AI Agents", 2026-08-05) and Onshape's branch model, where a branch is a cheap pointer/workspace rather than a full copy, so many attempts can be tried and discarded cheaply (**observed**, onshape.com/en/features/branch-merge-cad, 2026-08-05).

**Granularity of a single tool call.** Evidence favors "atomic-but-typed," not either extreme. SheetCopilot found collapsing a task into one high-level composite action (a single CreateChart call) measurably hurt correctness (Exec@1 down 12.6%, Pass@1 down 6.1%) because the call's own surface was too complex to use reliably, while token-level/lowest-level actions cause unstable decision-making over long horizons (**observed**, arxiv.org/pdf/2305.19308; arxiv.org/html/2605.18597, 2026-08-05). Applied here: "add a cube" is safe but slow toward a finished scene; "add a staircase with 12 treads" is efficient but is exactly the composite call research shows agents mis-parameterize. The evidence favors a middle skill library — typed, named, parametric operations ("add_staircase(treads=12, rise=…, run=…)") small enough to get each parameter right and to validate structurally (**inferred**).

## Multi-agent division models

| Model | How work splits | Collision risk | What it needs | Precedent |
|---|---|---|---|---|
| By object | Each agent owns one discrete object (chair, railing) | Shared attachment points/joints across owners | Read-only shared layout graph others can reference, not write | SceneWeaver's role-agents share one object-relationship graph (**observed**, dl.acm.org/doi/10.1145/3769534.3769540, 2026-08-05) |
| By subsystem (structure/detail/materials/lighting) | Whole-scene passes, one subsystem at a time | Low for concurrency, high for invalidation (detail pass can break earlier topology) | Deterministic pass ordering; each subsystem writes its own composable layer | USD layer stack: departments author non-destructive overrides on separate layers, composited by strength order (**observed**, developer.nvidia.com, 2026-08-05) |
| By phase (blockout->refine->detail->polish) | Baton-passed, one agent/phase active at a time | Near zero — mutual exclusion by construction; no parallelism | A phase-gate/promotion criterion before handoff | The art pipeline itself; SceneConductor's staged init -> construction -> refinement (**observed**, arxiv.org/html/2606.08402, 2026-08-05) |
| By spatial zone (rooms/regions) | Scene partitioned into non-overlapping bounding regions | Seams at boundaries (shared walls, doorways) | Boundary/handshake contract between adjacent owners | MA3DSG's graph-alignment step merges partial per-agent subgraphs into one global graph (**observed**, arxiv.org/abs/2602.04152, 2026-08-05) |
| Critic/maker pairing | One agent proposes, a separate agent validates before commit | None for concurrency (single writer); risk of ping-pong loops | Shared checkable constraint list + termination budget | I-Design's Layout Corrector + Refiner fix an initial layout agent's invalid placements (**observed**, arxiv.org/pdf/2404.02838, 2026-08-05) |

The two richest precedents for avoiding collisions *without locks* are USD and Onshape, and neither uses record-level locking. USD resolves concurrent authorship by composition order — a deterministic "which layer wins" rule — not by preventing simultaneous writes (**observed**, developer.nvidia.com, 2026-08-05). Onshape treats a branch as a cheap pointer, diffs at the *feature* level, flags true geometric conflicts in red, and requires resolution only of what's flagged (**observed**, onshape.com/en/features/branch-merge-cad, 2026-08-05). Figma's property-level last-writer-wins is the outlier worth naming and avoiding for geometry: it works because two people rarely edit the same design property simultaneously, but geometric edits (move a wall vs. attach a railing to it) are exactly where silent last-writer-wins produces invalid results, not just a UI surprise (**observed**, hellointerview.com "How Figma Built Multiplayer Editing on Simplified CRDTs", 2026-08-05).

## The artist's blockout -> polish progression, and which stages an agent can own
Standard pipeline (**observed**, gdp.academy "Complete Guide to the 3D Pipeline #1: Blocking-out"; hyper3d.ai "Game Art Pipeline 3D"; tripo3d.ai "Game Development Process", 2026-08-05): concept/reference -> **blockout/greybox** (primitives, proportion, no detail) -> **high-poly sculpt** (organic form, silhouette) -> **retopology** (clean quad low-poly for deformation/real-time) -> **UV unwrap** -> **texture bake + PBR material painting** (albedo/roughness/metallic/normal) -> **rigging/weight painting** (if animated) -> **lighting/engine integration + optimization**.

This progression is *why* human work doesn't look like glued-together boxes: blockout is deliberately boxes, and every later stage exists specifically to convert boxes into an intentional, continuous surface. The "not stitched together" quality is the output of the sculpt/retopo passes, not of one generation step (**inferred**, synthesized from the pipeline sources plus the failure-mode evidence below).

Per-stage agent readiness (**inferred**, from the failure-mode and tool-capability evidence gathered):
- **Blockout/greybox — agent can own this today.** Parametric/primitive tool calls (bpy create_object, Embodied CAD's typed operations) already do this well; it's the stage current AI-Blender integrations demonstrate (**observed**, github.com/ahujasid/blender-mcp, 2026-08-05).
- **Retopology / UV — agent can own via orchestration, not judgment.** These are algorithmic (auto-retopo, auto-unwrap); an agent can invoke the algorithm and mechanically verify the result (manifold check, seam count, UV overlap) without needing aesthetic judgment.
- **Texture/PBR baking — partial.** Describable as tool calls (bake albedo, generate normal/roughness maps), but exactly where today's tools fail most visibly — seams, stretching, missing PBR channels top the failure-mode literature (**observed**, tripo3d.ai, 2026-08-05).
- **High-poly organic sculpting — agent cannot reliably own this yet.** Requires the judgment current tools lack — "triangle soup," "featureless blobs," welded limbs, anatomical errors are reported specifically here (**observed**, news.ycombinator.com/item?id=47157841; gamedeveloper.com, 2026-08-05).
- **Rigging — agent cannot reliably own this yet.** Underdeveloped even in leading commercial tools (**observed**, agentbrisk.com AI 3D tools comparison, 2026-08-05).
- **Lighting/polish — partial.** Applying presets/HDRIs and render-and-compare is tractable (BlenderMCP already pulls HDRIs from Poly Haven); final aesthetic judgment stayed human-led in every tool surveyed.

## Where journeys break (observed complaints)
- No iterative editing on generated meshes — "I cannot. There are no loops. I would have to sculpt it like clay" (news.ycombinator.com/item?id=47157841, 2026-08-05).
- Generated geometry as "triangle soup" lacking rigging-ready structure; rebuilding from scratch often faster than fixing AI topology — "not a shortcut but rather a more power intensive way to generate technical debt" (same thread, 2026-08-05).
- Single-piece meshes with no meaningful part separation, welded limbs, asymmetrical organic forms (gamedeveloper.com "How devs can spot AI-generated 3D models", 2026-08-05).
- Non-manifold geometry, scale/proportion errors, texture seams/stretching, missing PBR maps, bake distortion — a cataloged failure list with no live way to catch them during generation (tripo3d.ai, 2026-08-05).
- Long-running agents give no progress signal, so users can't tell "working" from "stuck," and a bad result after a long wait is worse than a fast miss (GitLab issue #1351; uxtigers.com "Slow AI", 2026-08-05).
- No undo/checkpoint safety net in the current reference tool — the operator is explicitly told to save manually before letting the agent run code (github.com/ahujasid/blender-mcp, 2026-08-05).
- Hard-surface/mechanical results called "horrendous" by reviewers while organic/anatomical results are separately weak — no surveyed tool covers both well, so trust breaks differently by subject matter (see3d.art / stacksheriff Meshy reviews, 2026-08-05).

## Decisions for the user
- **Perception channel** — rendered images, structured scene-graph text, or both? Text-only is cheap/precise but blind to visual defects; images-only catches what a human sees but costs ~700-1300 tokens per 1024x1024 frame and current VLMs still "catalogue" rather than grasp 3D scenes; hybrid diffs text every call and renders at checkpoints. Recommendation: hybrid. Impact: high. Evidence: roboflow.com image-token-cost post; arxiv.org/html/2605.20448 (2026-08-05).
- **Verification authority** — agent's own visual judgment, deterministic geometry checks, a constraint solver, or a human gate? Only geometry/solver checks give a hard pass/fail. Recommendation: deterministic checks mandatory, render-compare secondary, human gate only at phase boundaries. Impact: high. Evidence: Embodied CAD solver-feedback loop; Render-in-the-Loop paper (2026-08-05).
- **Tool-call granularity** — one giant call per composite structure, one call per primitive, or a curated skill library of typed parametric operations? Recommendation: skill-library middle ground. Impact: high. Evidence: SheetCopilot's measured correctness drop from over-composite actions (arxiv.org/pdf/2305.19308, 2026-08-05).
- **Checkpoint/undo model** — continuous auto-checkpoint per call, checkpoints only at phase boundaries, or none (today's status quo)? Recommendation: cheap per-call checkpoint on the active object plus named phase-boundary checkpoints for full-scene rollback. Impact: high. Evidence: BlenderMCP's manual-save warning as counter-example; coding-agent checkpoint literature (github.com/ahujasid/blender-mcp; digitalapplied.com, 2026-08-05).
- **Multi-agent split strategy** — by object, subsystem/layer, phase, spatial zone, or critic/maker pairing (not exclusive)? Recommendation: phase-gated by default, with object-level parallelism inside blockout and detail phases only, where a shared scene graph already defines clean ownership. Impact: high. Evidence: USD-layer and Onshape-branch precedents both favor structured composition over free concurrency (developer.nvidia.com; onshape.com, 2026-08-05).
- **Conflict resolution when sub-agents' work overlaps** — hard locks, optimistic feature-level merge with flagged conflicts (Onshape-style), layered composition with deterministic strength order (USD-style), or property-level last-writer-wins (Figma-style)? Recommendation: USD-style layering for the working scene plus Onshape-style flagged conflicts at merge points; avoid silent last-writer-wins for geometry. Impact: medium-high. Evidence: hellointerview.com Figma writeup contrasted with the USD/Onshape sources (2026-08-05).
- **Autonomy default** — fully autonomous run-to-completion, step-by-step confirmation, or supervised-by-default with an adjustable autonomy budget? Recommendation: supervised-by-default; raise the budget once trust is established. Impact: high. Evidence: agent-ops guidance that higher capability is not a reason to remove supervision (digitalapplied.com, 2026-08-05), reinforced by the density of domain-specific quality complaints (tripo3d.ai; HN thread, 2026-08-05).
- **What the operator sees during a live build** — full streamed viewport, periodic rendered snapshots, a text action-log only, or a highlighted diff of the latest change? Recommendation: throttled snapshots at natural pause points plus a running action-log and an explicit "what changed" highlight. Impact: high. Evidence: GitLab progress-indicator complaint; uxtigers.com's "conceptual breadcrumbs / progressive disclosure" guidance (2026-08-05).
- **Target granularity for "point at what's wrong"** — vertex/face-level picking, whole-object picking, named-part/bounding-box selection, or free-text region description? Recommendation: object/named-part selection mapped to scene-graph coordinates for persona (a); expose finer vertex/edge picking as a power option for persona (b). Impact: medium. Evidence: single-piece-mesh complaint shows there's often no clean "part" to select in current AI output (gamedeveloper.com, 2026-08-05).
- **Export gating** — always allow export, gate behind a validity checklist (manifold/UV/scale) with override, or export with a non-blocking warning banner? Recommendation: checklist-gated export with explicit override, since defects invisible in-viewer are what surface downstream as the worst failure moment. Impact: medium. Evidence: tripo3d.ai failure-mode catalog (2026-08-05).
